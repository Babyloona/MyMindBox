# MindBox — внешняя память в Telegram

Бот сохраняет факты, фото и файлы с подписью, а по вопросу своими словами возвращает нужную заметку или файл. Если такого не записано, честно отвечает «Такого не записано» и ничего не выдумывает.

**Для кого.** Человек записывает бытовые детали (где лежит вещь, рецепт, дело со сроком, документ, что купить), а потом ищет их вручную: листает чаты, «Избранное» и галерею. Бот находит запись по смыслу, даже если слова в вопросе другие: «где зарядка?» → «провода в чёрном чемодане на балконе».

## Как это устроено

```
Telegram (aiogram)
   │
   ▼
защита секретов (регулярные выражения) ── пароль / карта / ИИН ──► отказ, текст никуда не уходит
   │
   ▼
граф LangGraph
   есть файл? ── да ──────────────────────────────► save (с проверкой дублей) ─► Chroma
   │ нет
   classify (LLM): save / search / search_all
   │ поиск
   retrieve: локальные эмбеддинги + Chroma, фильтр по пользователю
   grade: порог сходства, без LLM ── ниже порога ──► «Такого не записано»
   verify (LLM): какая заметка отвечает на вопрос ── ни одна ──► «Такого не записано»
   ├─ уверенно ──────► заметка и файл
   └─ неуверенно ────► «Не уверен, но возможно, это оно: …»
   │
   ▼
журнал data/logs/requests.jsonl (id пользователя хешируется)  +  трейсы Langfuse
```

LLM вызывается не больше двух раз на запрос: классификация и проверка. Эмбеддинги локальные (`paraphrase-multilingual-MiniLM-L12-v2`), за них не платим.

## Запуск одной командой (Docker)

Нужны Docker, токен бота от @BotFather и ключ OpenAI.

```bash
cp .env.example .env        # впишите TELEGRAM_BOT_TOKEN и OPENAI_API_KEY
docker compose up --build
```

Первая сборка занимает 10–20 минут: скачиваются PyTorch и модель эмбеддингов.

Проверка, что сервис жив:
```bash
curl http://localhost:8080/health
# {"status": "ok", "service": "mindbox-bot"}
```

Заметки и журнал лежат на томе `mindbox_data` и переживают перезапуск и пересборку контейнера.

## Запуск без Docker

```bash
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements-dev.txt
cp .env.example .env              # впишите ключи
python -m bot.bot
```

Версии библиотек закреплены в `requirements.txt` (проверено на Python 3.10).

## Настройки (.env)

| переменная | что это | по умолчанию |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота | обязательно |
| `OPENAI_API_KEY`, `OPENAI_MODEL` | LLM для классификации и проверки | `gpt-4.1-mini` |
| `LLM_PROVIDER` | `openai` или `groq` (запасной) | `openai` |
| `EMBEDDING_PROVIDER` | `local` или `openai` | `local` |
| `VERIFY_TOP_K` | сколько кандидатов проверяет LLM при поиске одной заметки | `3` |
| `SEARCH_ALL_TOP_K` | сколько заметок достаётся на «покажи все» | `10` |
| `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, `LANGFUSE_HOST` | трейсинг (необязательно) | выключен |
| `HEALTH_PORT` | порт ручки здоровья | `8080` |

`.env` в репозиторий не попадает (`.gitignore`, `.dockerignore`), в `.env.example` только имена переменных.

## Проверки

```bash
python -m pytest tests -v          # 22 теста, без сети и без моделей
python scripts/check_env.py        # ключи, связь с OpenAI и Langfuse, трейс одного запроса
```

При старте бот сам проверяет связь с Langfuse: SDK при неверных ключах молчит, поэтому проверка явная.

## Качество

Замер на оценочном наборе из 49 вопросов (типовые, разговорные, «покажи все», отказы, пограничные отказы), сравнение пяти ступеней лестницы и двух улучшений, интервалы и парные сравнения — в `MindBox_Final_Project.ipynb`, разделы 6–10. Презентация — в `docs/`.


## Ограничения

- Поиск идёт только по тексту подписей: содержимое фото и документов бот не читает.
- Текст обычных заметок уходит во внешний LLM-сервис. Пароли, номера карт и ИИН отсекаются до отправки, но защита работает по шаблонам и ловит не всё.
- При смене модели эмбеддингов старые заметки не видны: у каждой модели своя коллекция, нужна переиндексация.
- Качество измерено на 15 заметках. Поведение на тысячах заметок не проверено.
- Не подходит для данных, где пропуск дорого стоит (медицина, юридически значимые записи): бот может не найти запись, и человек решит, что её нет.
